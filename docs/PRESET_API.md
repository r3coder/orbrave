# 프리셋 서버 API

오브 페이지(`index.html`)에서 만든 프리셋을 서버에 올리고, 무한 플레이어(`play.html`)가 그 프리셋들을 무작위로 재생합니다.
이 저장소에는 프론트엔드만 있습니다. 서버는 아래 계약만 맞추면 어떤 언어로 만들어도 됩니다.

- 프론트 클라이언트: `src/presetApi.js`
- 데이터 형식: `src/orbPreset.js`의 `toWire` / `fromWire` / `songToWire` / `songFromWire`
- 입력 검증: `server/presetSchema.mjs`의 `validatePreset`
  - 서버와 오브 페이지가 같은 파일을 씁니다. 그래서 공유 창과 서버가 같은 오류 메시지를 보여 줍니다.
- 서버: `server/index.mjs`(배포용, 의존성 없음), `server/presetApi.mjs`(요청 처리), `server/presetStore.mjs`(파일 저장)
- 개발 서버: `npm run dev`와 오브 개발 서버(`vite.orbs.config.js`)에서 `tools/presetDevApi.js`가 같은 처리기로 `/api/presets`를 제공합니다.
  - 데이터는 `.preset-data/`에 저장됩니다.

## 저장 방식

- 프리셋 하나가 JSON 파일 하나이고, 날짜(UTC)별 폴더에 나뉘어 저장됩니다.
  - 예: `server/data/presets/2026-11/04/261104-k3j9x2abq0.json`
- id 앞부분이 날짜라서 `GET /presets/:id`는 바로 그 파일을 엽니다.
- 한 폴더에는 하루 치만 들어가고, `PRESET_MAX_PER_DAY`(기본 2000)를 넘으면 그날은 더 받지 않습니다(`503`).
- 임시 파일에 쓴 뒤 이름을 바꾸는 방식이라 읽는 쪽이 반쯤 쓴 파일을 볼 일이 없습니다.
- 파일을 읽을 때도 다시 검증해서, 손으로 고치거나 깨진 파일은 목록에 나오지 않습니다.

## 주소

- 기본값은 같은 출처의 `/api`입니다.
- 다른 주소를 쓰려면 빌드할 때 `VITE_PRESET_API=https://example.com/api`처럼 지정합니다.
- 출처가 다르면 서버가 CORS로 `GET`, `POST`와 `Content-Type` 헤더를 허용해야 합니다.
  - 이 저장소의 서버(`server/index.mjs`)는 `PRESET_ALLOWED_ORIGINS`에 적은 출처만 허용합니다.
  - 배포 구성: 사이트는 GitHub Pages(`https://r3coder.github.io/orbrave/`), API는 `https://r3c0d3r.mooo.com/orbrave/api`(`.env.production`).

## 프리셋 객체

```json
{
  "id": "lq3k9x2a",
  "name": "밤 산책",
  "author": "",
  "description": "",
  "kind": "orb",
  "createdAt": "2026-11-04T12:00:00Z",
  "layers": ["kick", "openHat", "drawn3"],
  "drawn": [{ "id": "drawn3", "src": "acid", "raw": "..7.7...3..........7777......." }],
  "variation": 4821
}
```

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | `[A-Za-z0-9_-]{1,64}` | 서버가 정합니다. 공유 링크 `#preset.<id>`에 쓰입니다 |
| `name` | 문자열, 32자 이하, 필수 | 노래 제목 |
| `author` | 문자열, 24자 이하, 생략 가능 | 노래 저자 |
| `description` | 문자열, 261자 이하, 생략 가능 | 노래 설명. 사용자가 쓰는 부분은 100자이고, 오브 페이지가 CC-BY 소리(피아노, Wurlitzer)를 쓴 조합이면 뒤에 `Credits: …` 저작자 표시를 붙여 보냅니다 |
| `kind` | `"orb"` 또는 `"stem"` | 오브 조합만인지, 전체 곡(스템)까지인지 |
| `createdAt` | ISO 8601 | 서버가 정합니다. 정렬과 표시에 씁니다 |
| `layers` | 문자열 배열, 1–24개 | 오브 id(`src/orbCatalog.js`의 `LAYERS`) 또는 `drawn`의 id |
| `drawn` | 배열, 8개 이하 | 피아노 롤로 그린 파트 (아래 참고) |
| `variation` | 0 이상의 정수 | 변주 시드 |
| `seeds` | 객체, 생략 가능 | 따로 변주한 악기: `{ 오브 id: 시드 }` (`layers`에 있는 id만, 나머지는 `variation`) |
| `gains` | 객체, 생략 가능 | 따로 음량을 바꾼 악기: `{ 오브 id: 퍼센트 }` (5–400 정수, `layers`에 있는 id만, 나머지는 100) |
| `song` | 객체, `kind: "stem"`일 때만 | 스템 그리드 (아래 참고) |

글 필드(`name`, `author`, `description`)는 공백을 하나로 줄인 뒤 검사합니다. 다음이 들어 있으면 거절합니다.
- 제어 문자, 폭이 없는 문자, 글자 방향을 바꾸는 문자 같은 보이지 않는 문자
- `< > { } \` \\`, HTML 엔티티, `javascript:`, `on…=`, 링크(`http:`, `www.`, `xxx.com` 같은 도메인)

`song`은 전체 곡을 4마디 칸 단위로 적은 것입니다.
```json
{
  "sections": [{ "name": "드롭", "len": 16, "shift": 0, "v": 0 }],
  "rows": [{ "id": "kick", "alt": false, "cells": [4821, 4821, null, -1] }]
}
```
- `sections`: 1–12개. `len`은 4의 배수(4–64마디), `shift`는 조옮김(−11–11), `v`는 섹션 변주(0–100)입니다.
- `rows`: 1–40개. 악기 한 줄마다 칸 수가 모든 섹션 칸 수의 합과 같아야 합니다.
  - 칸 값: `null`은 쉼, `-1`은 시드 없이 연주, 0 이상은 그 시드로 연주입니다.
  - `alt: false`인 줄은 `layers`에 있는 id여야 합니다. `alt: true`는 곡 뒷부분에서 바꿔 끼우는 오브입니다.

`drawn` 항목은 다음 세 필드로 이루어집니다.

| 필드 | 설명 |
|---|---|
| `id` | 32자 이하. `layers`에서 이 id로 참조합니다 |
| `src` | 악기로 쓴 오브 id |
| `raw` | 16분음표 64칸. 한 칸은 `.`(빈칸), 36진수 행 번호 한 글자(0–e), 또는 괄호로 묶은 화음(`(047)`)입니다. 화음이 없으면 정확히 64자입니다 |

**코드는 절대 오가지 않습니다.**
프리셋에는 오브 id, 그림, 숫자만 들어 있고, Strudel 코드는 받는 쪽 브라우저가 카탈로그를 보고 다시 만듭니다.
그래서 서버가 코드 실행 문제를 걱정할 필요는 없습니다.
모르는 오브 id나 형식이 틀린 항목은 프론트가 알아서 버립니다.
재생할 수 있는 파트가 하나도 없는 프리셋은 목록에서 빠집니다.

## 엔드포인트

### `GET /presets?limit=200`
최근에 올라온 것부터 프리셋 목록을 돌려줍니다.
메인 플레이어는 페이지를 열 때 한 번, 그 뒤로는 3분마다 이 목록을 다시 받습니다.
```json
{ "presets": [ { …프리셋 객체… } ] }
```

### `GET /presets/:id`
프리셋 하나를 돌려줍니다. 없으면 `404`입니다. 공유 링크로 들어온 곡을 찾을 때 씁니다.

### `POST /presets`
오브 페이지의 **☁ 서버 공유** 창(또는 내 프리셋 타일의 ☁)에서 **서버에 공유**를 누르면 호출됩니다.
요청 본문은 다음과 같습니다(`id`, `createdAt` 없음).
```json
{ "name": "밤 산책", "author": "R3C0D3r", "description": "새벽 산책 느낌", "kind": "orb",
  "layers": ["kick", "drawn3"], "drawn": [{ "id": "drawn3", "src": "acid", "raw": "…" }], "variation": 4821,
  "agree": true, "website": "" }
```
- `agree`: 업로드 동의 체크. `true`가 아니면 거절합니다.
- `website`: 화면에 안 보이는 봇 함정 칸. 값이 있으면 거절합니다.
- 둘 다 저장되지 않습니다. 모르는 필드도 버립니다.

응답은 `201`과 함께, `id`와 `createdAt`이 채워진 프리셋 객체입니다.

서버가 막는 것:
- `Content-Type: application/json`이 아닌 요청 (`415`)
- 32 KB를 넘는 본문. 끝까지 받지 않고 끊습니다 (`413`)
- 허용하지 않은 다른 사이트에서 보낸 요청 (`403`)
- 같은 주소에서 10분에 5번 넘게, 또는 15초 안에 다시 올리는 것 (`429`)

### `POST /presets/:id/vote`
공유된 곡에 👍 / 👎를 남깁니다. 오브 페이지(모두의 곡을 불러왔을 때)와 무한 재생(공유된 곡이 재생 중일 때) 재생 버튼 오른쪽 버튼이 호출합니다.
```json
{ "voter": "50940c96-711c-466b-a956-6a163b67d445", "v": 1 }
```
- `voter`: 브라우저마다 한 번 만들어 localStorage(`orbVoter`)에 두는 무작위 id. `[a-z0-9-]{16,40}`.
- `v`: `1`(👍), `-1`(👎), `0`(취소). 같은 `voter`가 다시 보내면 앞의 평가를 바꿀 뿐 더해지지 않습니다.
- 응답: `200 { "ok": true, "v": 1 }`. 없는 프리셋은 `404`.
- 같은 주소에서 10분에 60번까지, 0.3초 간격 (`429`). 다른 사이트에서 보낸 요청은 `403`.
- 평가는 `<dataDir>/votes.json`에 `{ 프리셋 id: { voter: 1 | -1 } }`로 저장됩니다(2초 모아서 기록).

**득표 수는 밖으로 나가지 않습니다.**
`GET /presets` 목록의 각 프리셋에 가중치 `w`만 붙습니다.
- 평가가 없으면 `1`. (👍 − 👎)가 3 늘 때마다 2배, 줄 때마다 절반이고, `0.25`–`4` 사이로 묶입니다.
- 무한 재생은 다음 곡을 `w`에 비례해 고르고, 떠다니는 라벨과 오브 페이지의 모두의 곡 목록(최대 100개)은 `w`와 최신순을 섞은 무작위 순서로 보여 줍니다.
- 화면 어디에도 `w`나 득표 수는 표시하지 않습니다.

### 오류
- 2xx가 아닌 응답의 본문은 `{ "error": "사람이 읽을 메시지" }` 형식으로 보냅니다.
- 오브 페이지는 이 메시지를 공유 창에 그대로 보여 줍니다.

## 서버에서 해 줘야 할 것

- 위 검증, 크기 제한, 도배 방지는 `server/`에 구현돼 있습니다.
- 아직 없는 것:
  - 욕설 필터, 신고와 숨김 같은 관리 기능
  - 삭제와 수정 API
- 올라온 곡을 내리려면 저장 폴더에서 그 JSON 파일을 지우고 서버를 다시 시작합니다.
  - 목록은 메모리에 캐시되기 때문에 다시 시작해야 반영됩니다.
  - 목록에서 빠지면 메인 플레이어에도 나오지 않습니다.
- 메인 플레이어는 스템 프리셋도 오브 조합으로만 재생합니다. 스템 그리드대로 재생하는 건 아직 없습니다.

## 프론트 동작 요약

- **서버에 프리셋이 하나라도 있을 때**
  - 메인 화면에 떠다니는 라벨이 장르 대신 유저 프리셋(최대 14개)으로 바뀝니다.
  - 라벨을 클릭하면 그 프리셋이 바로 재생됩니다.
  - 다음 곡도 무작위 유저 프리셋입니다.
- **서버가 없거나, 비어 있거나, 응답하지 않을 때(6초 제한)**
  - 지금처럼 장르 라벨과 자동 작곡으로 돌아갑니다.
- 각 프리셋은 약 56마디 곡으로 재생됩니다. 순서는 intro → main → break → main2 → outro입니다.
  - intro와 break, outro는 사용자가 고른 파트 중 일부를 빼서 만듭니다.
